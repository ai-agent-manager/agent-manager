Create the comprehensive Confluence Epic Break-down Analysis document with all
7 sections.

Use this exact structure:

Epic Break-down Analysis: [Project Name]
Epic Planning Document
Created by: Epic Elaboration Agent
Date: [Today's date]
Status: Draft – Awaiting Team Review

1. Executive Summary
Project: [Project Name]
Total Epics: [N] epics ([X] Must-have, [Y] Should-have, [Z] Could-have)
Estimated Effort: [X–Y] story points total
Target Timeline: [X–Y] months ([N] phases)
Critical Dependencies: [list]
Key Risks: [list]

2. Epic Overview Table
[Table: Epic ID, Epic Name, Priority, Size, Dependencies, Rationale, Phase]

3. Detailed Epic Breakdown
For each epic:
  Epic [N]: [Epic Name]
  Scope: [2–4 sentences]
  Goals:
    Customer Goal: [What customer can do/achieve]
    Business Goal: [Business outcome/metric]
  Priority: [Must/Should/Could/Won't]
  Justification: [Why this priority]
  KPIs: [3–5 measurable metrics]
  Assumptions: [list]
  Dependencies:
    Technical: [Technical dependencies]
    Business: [Business dependencies]
    External: [External dependencies or "None"]
  Rationale:
    Why this epic: [Business value, customer need, technical necessity]
    Why this priority: [MoSCoW justification]
    Why this phase: [Sequencing rationale]
    Why this scope: [Scope decisions]

4. Dependency Diagram
[Visual or text-based diagram showing epic dependencies]
Critical Path: [Longest dependency chain]
Parallelizable Work: [Epics that can run in parallel]
External Dependencies: [Dependencies on external teams/systems]

5. Proposed Implementation Order
For each phase:
  Phase [N]: [Phase Name] (Sprint [X–Y], [N] weeks)
  Epics: E[X]: [Epic Name]
  Rationale: [Why these epics in this phase, why this order, what this phase delivers]
  Capacity: [X] story points, [N] teams

6. Requirements Traceability Matrix
[Table: Requirement ID, Requirement, Epic IDs, Coverage]
Coverage Summary:
  Fully Covered: [N] requirements ([X]%)
  Partially Covered: [N] requirements ([X]%)
  Not Covered: [N] requirements ([X]%)
Gaps/Risks: [list]

7. Open Questions & Assumptions
Open Questions (Need Decisions):
  Q1: [Question] – Owner: [Name/Role] – Impact: [What's affected]
Assumptions (Need Validation):
  A1: [Assumption] – Validate with: [How/Who] – Risk if wrong: [Impact]

Status: Draft – Awaiting Team Review

  1. Team reviews this document
